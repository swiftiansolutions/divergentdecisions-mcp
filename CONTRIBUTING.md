# Contributing

This is a closed beta. That shapes what contributing means here.

## Code contributions

Pull requests are not accepted in the closed beta. The codebase is stabilising and the author is sole maintainer at this stage. This will change in a future phase.

## What actually helps right now

**File bug reports.** A clear, reproducible bug report is a direct contribution to the tool. Use the [bug report template](../../issues/new?template=bug_report.md). The more specific the better — MCP server version, Claude Desktop version, OS, exact steps, what you expected, what happened.

**File feedback.** If something was confusing, slow, or created friction, say so. If something worked better than you expected, say that too. Use the [feedback template](../../issues/new?template=feedback.md). There are no wrong answers in a beta.

**Start a discussion.** If you are not sure whether something is a bug or intended behaviour, or you want to share how you are using the museum, [Discussions](../../discussions) is the place. Others may have the same question or be doing the same thing.

## Protocol questions

Questions about the Idea Museum protocol itself — how bootstrap works, what a SIP is, how to structure catalogue cards — belong in the [idea-museum repository](https://github.com/swiftiansolutions/idea-museum/issues), not here. This repo is the implementation; that repo is the standard.

## Conduct

Be direct, be specific, be kind.
